过去我可能过多的局限在了数据结构和算法中了，从而当我想转AI全栈的时候有点本末倒置了。随着现在AI工具属性的增强，对于算法的定义已经变了。现在更应该做的是将视角放在提示词工程上。而不是聚焦在力扣上，当力扣的热题100还是得刷一下的，因为这也是个人能力的体现，在面试中可能会经常遇到。我准备采取抓大放小的方式，从最核心到锦上添花过渡

	将能力放到工程落地上，现在的新名词概念层出不穷。不要过于学院派，导致本末倒置

## AI开发需要掌握的工程算法「最重要」

### RAG 阶段的「文本切分与检索算法」

- **滑动窗口算法（Sliding Window / Overlap）：** 当你把一本 10 万字的书切成一段段 500 字的碎片时，怎么让相邻的碎片有 10% 的重叠，从而不漏掉上下文信息？
    
- **余弦相似度（Cosine Similarity）：** 向量数据库是如何计算用户问题和知识库文档之间的相似距离的？不需要你手写公式，但你需要从直觉上理解它的数学含义（夹角越小，含义越接近）。

### 启发式重试与流控算法

AI API 极其不稳定，频繁并发会导致 `429 Too Many Requests`（限流）或超时。

- **指数退避重试算法（Exponential Backoff）：** 当大模型接口报错时，不要立刻重试，而是等待 1 秒、2 秒、4 秒、8 秒……指数级增加等待时间，直到成功。
    
- **令牌桶/漏桶算法（Token Bucket）：** 独立开发时，如何控制你的用户每分钟最多消耗多少 Token，防止被薅羊毛破产？

### 基于 Prompt 的「推理控制算法」

写 Agent 时，你的“算法”其实是用 Prompt 和逻辑代码拼装起来的：

- **COT（思维链，Chain of Thought）：** 让大模型一步步思考。
    
- **TOT（思维树，Tree of Thoughts）：** 让大模型针对一个问题生成 3 个方案，然后评价哪个最好，放弃不好的方案，沿着好的方案继续往下搜索。这本质上是把**传统的树状搜索算法变成了用提示词来控制**。
