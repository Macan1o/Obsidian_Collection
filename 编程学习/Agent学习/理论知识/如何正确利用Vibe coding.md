### 引言

> 本文核心目的是在当前AI浪潮下，如何不让自己的技术被架空

结合我的实际经历来说，借助AI的效果是显而易见的，大幅提高了我的开发速度。让简历变得光鲜，但于此同时就是华而不实。这点在面试中体现得很深刻，比如：

	AI开发完成后虽然会借助AI梳理业务逻辑链路，但涉及到具体场景细节的时候就哑火了，当面试官问：chart skill前端是如何渲染出可操作性的图片的？这里为什么用了这个技术栈而没有用那个技术栈？这样设计的逻辑是什么？

这种问题多出在决策理由，底层技术细节层面，那么为什么会造成上述问题？

#### 出在Vibe Coding的隐形代价上。

- 传统模式下，技术判断力是像下面这样增长
	遇到问题 → 查资料 → 对比方案 → 做决策 → 写代码 → 踩坑 → 排查 → 记住
	
- Vibe Coding下的流程
	描述需求 → Agent 生成代码 → 能跑 → 下一个需求

#### 最终结果很明显，说不清任何一个项目的关键决策

因此解决上述问题，不仅要将视角放到宏观的项目角度，还要放到微观上的决策与技术细节！

#### 如何更有效地复盘？

- 当涉及到架构决策、业务逻辑的时候，问清楚为什么这样写，权衡了哪些因素？
	
- 当出现bug的时候，按照错误现象 → 诊断路径 → 根因 → 修复策略链路走
	
- 每个方案都带反事实追问，如果数据量增大几倍，或者换成另外一种技术栈，方案还成立吗？

### 结语

AI 写代码的效率，和技术能力的增长，不应该是互斥的。AI永远是赋能的工具
