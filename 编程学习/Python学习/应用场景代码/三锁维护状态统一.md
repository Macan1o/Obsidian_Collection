## 同路径互斥锁


> [!NOTE] 代码路径
> 示例代码路径在 Python_Study/同路径互斥锁.py

### 基本逻辑

```
workspace_path → 一把专属 Lock
Turn A 进来：acquire 成功 → 跑 CLI
Turn B 同路径：卡在 acquire，直到 A release（或超时失败）
不同路径：各用各的锁，互不影响
```


### 加固 Session 池逻辑

先走`get_or_create` 逻辑：

```
已有该 run 的活 session
  → 若 BUSY → 直接报忙
  → 若 IDLE → 标 BUSY 复用

没有 → 看数量
  → 未满 → 新建
  → 已满 → 先踢最老的 IDLE
  → 全是 BUSY、踢不动 → ShellSessionPoolFullError
```


### 三层架构

```
用户发消息（Hybrid）
        │
        ▼
  Session 池有空位？
        │否
        ▼
  全局队列 enqueue（FIFO）──等待──► drain 时再续跑
        │是
        ▼
  get_or_create(shell)（池内锁保护）
        │
        ▼
  workspace_cli_turn(同路径互斥锁)
        │
        ▼
  真正跑 CLI / 写工作区
        │
        ▼
  mark_idle → 通知队列 drain 下一位
```


## 池内锁

> 锁整张 session 字典

```
1. with self._lock:          # 进入池内临界区（通常瞬间拿到）
2.   看 _sessions[run_id]
     ├─ 已有且活着
     │    ├─ 已是 BUSY/CREATING → 抛 ShellSessionBusyError（不是锁超时）
     │    └─ IDLE/READY → 标成 BUSY，return（复用）
     └─ 没有
          ├─ 活跃数 < 上限 → 创建并登记，标 CREATING/BUSY
          ├─ 已满 → 尝试踢最老 IDLE
          │         ├─ 踢成功 → 腾出名额再建
          │         └─ 全是 BUSY 踢不动 → ShellSessionPoolFullError
3. （锁外）真正 spawn PTY —— 注意：耗时的起进程尽量不长时间占着 _lock
4. 再短持锁：确认登记、标 BUSY
```



## file_lock

> 操作系统对文件描述符的咨询锁

```
1. handle = open(path, "a+" / "r+")     # 先打开文件
2. with file_lock(handle):              # 对 fd 加排他锁
3.     seek(0) → read 全部内容
4.     在内存里改 JSON（append / pop）
5.     seek(0) → truncate → write 回去
6. 出 with → flock UNLOCK               # 释放文件锁
7. close（由 with open 负责）
```
