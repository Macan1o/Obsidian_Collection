[[LangGraph运转链路]]


## 简单编译链路

- 保存工作流配置
	
- 节点注册并完成处理逻辑映射
	
- 注册边特别是条件边
	
- 注册人工审核节点，将节点注册进 LangGragh 的 `interrupt_before`


#### 数据落盘

- 通过两种模式：编辑画布/编辑JSON完成信息配置，这个过程涉及到双模式转换逻辑「线性无条件边转换」
	 
- 发POST请求到后端通过后端JSON Schema完成校验后写入对应文件夹磁盘


#### 工作流执行

- 发送Post请求，后端的`chat_runner.py` 的 `_run_workflow()`接管。
	
- begin_workflow() 进行编译 + 首次调用
	- ① `compile_workflow(workflow)` 
		把 Workflow JSON 编译成 LangGraph 可执行图（见阶段三），注册 5 种节点 handler + 条件边 + interrupt_before
	- ② `workflow_run_config(run_id)`
		生成 {"configurable": {"thread_id": run_id}}，这是 LangGraph 识别"同一次运行"的钥匙
	- ③ `initial_compiler_state()`
		创建初始 CompilerState：status="idle"、node_outputs={}、current_instruction=<用户指令> 等
	- ④ `compiled.invoke(state, config)`
		真正启动 LangGraph 图执行，从 START → start → ... 一路跑到遇 interrupt_before 或 END，LangGraph 自动遍历节点「根据五节点映射事件」
	- ⑤ `is_awaiting_human_gate()`
		检查图是否挂在了 human_gate 前，如果是则设置 status="awaiting_human"
	
- `route_next()` — 路由决策中枢。每个节点注册完调用条件边函数决定下一步去哪（包括human_gate）

> 中间多Agent节点传递用到了节点输入解析算法

- 节点为 start 也就是初始化节点以及无上游节点的就以当前提示词为准
	
- 有上游节点的就以上游输出内容为准
	
- 多上游节点就对所有节点输出拼接「未来可以加 compaction（类似 chat compaction 的机制，在注入前压缩上游输出）」

### 问题解析

#### 人工审核节点的暂停与恢复机制实现？

基本流程就是当在暂停节点挂起前利用Checkpoint（MemorySaver）先保存完整的graph状态快照「已跑完节点后的 CompilerState（含 node_outputs 等）next = 下一个该跑的节点（门控 id）」，通过更新状态逻辑将人类决策注入到 CompileState 中，再利用LangGraph的Command（resume=）从断点继续执行

#### 为什么 JSON 里已经标记了 human_gate，还要注册 interrupt_before

`interrupt_before` 是 LangGraph 原生暂停逻辑，`_handle_human_gate` 是 Clutch 自己的消费/清理逻辑。JSON 中的 `type: "human_gate"` 只是一个标记，Compiler 读到它做了两件事：把它加入 interrupt_before 列表，以及为它注册 handler。

```
agent_task 完成
    │
    ▼
LangGraph 检测: 下一节点 human_gate ∈ interrupt_before
    │
    ▼ ⏸️ 挂起 + MemorySaver 保存 checkpoint
    │
    ▼ WS → human_required → 前端弹出审批卡片
    │
  ... 用户点击 Approve ...
    │
    ▼ update_state({human_decision: "approve"})
    ▼ invoke(Command(resume="approve"))
    │
    ▼ ▶️ 恢复，进入 _handle_human_gate
    │     ├─ 读取 human_decision = "approve"
    │     └─ 清除 check_result（防止 #52 bug：绕过失败检查后
    │         后续 gate 被旧 check_result 短路）
    │
    ▼ routing_signal → "approve" → 走 approve 边 → 继续下游
```

#### Checkpoint 是什么？

> Checkpoint = LangGraph 在每一个 "super-step"（节点执行完成）后自动保存的完整图状态快照。

通过 MemorySaver将 CompilerState 的全部字段保存为快照，避免用户审批时数据丢失

| 字段             | 示例值                                             |
| -------------- | ----------------------------------------------- |
| run_id         | `"run_abc123"`                                  |
| active_node_id | `"agent_1"`                                     |
| status         | `"running"`                                     |
| check_result   | "failed"                                        |
| human_decision | `""`                                            |
| node_outputs   | `{"agent_1": "## 研究报告\n...", "agent_2": "..."}` |
| task_logs      | `[...]`                                         |
| task_messages  | `[...]`                                         |
```
没有 checkpoint：
  挂起 → 用户审批 → 恢复 → "我在哪？刚才跑到哪了？数据呢？" 💥

有 checkpoint：
  挂起 → MemorySaver 写入快照 → 用户审批 → 
  invoke(Command(resume="approve"), config={"thread_id": run_id})
  → LangGraph 从快照恢复全部状态 → 从 human_gate 继续 → ✅
```
