## 策略路由

> [!NOTE] 核心思想
> 对多种 Agent 进行分类处理，避免进行层层 if 嵌套

先将多种 Agent 划分为两类：

- CLI 这种走 shell / 长驻 PTY ，就走 SHELL ，执行拼接命令等任务
	
-  兜底的云模型、MCP 工具循环，走内置 Agent，就走 NATIVE 策略

> 概括来说就是将多种 Agent 最后收束为两种运行策略，再统一进路由函数进行调度

```
20 个 Agent 名字
      ↓ 查 ProviderSpec
2 种运行策略
      ↓ 再进统一路由（engine_router）
上层只面对：给我 prompt，还我结果
```

## 解包

不同引擎输出的内容结构不同，可能返回字典，可能返回原始终端输出。导致渲染出现问题。因此需要解包

### 解包

将多种返回形式的结构中找到需要的内容

```
dict {"content": "你好", "reasoning_content": "..."}
        ↓ extract_content
"你好"

本来就是 "你好"
        ↓ extract_content
"你好"
```
