## 核心模块 `file_rewind.py`

### 存储位置

	{workspace}/.clutch/rewind/{run_id}/snapshots.json

> 存储的是要修改文件的所有代码内容

按run隔离，最多保留64条。写索引时用`file_lock`，防并发撕文件：

	snapshots.json可能同时被改，导致并发写坏同一份文件，因此先锁改完后放锁再由其他的Agent改写新的文件

### 单条快照结构

```JSON
{
  "path": "note.txt",          # 工作区相对路径
  "timestamp": 1699999999.0,
  "exists": True,              # 写之前文件是否存在
  "content": "original\n"      # 写之前的全文（不存在则为 ""）
}
```

### 对外函数功能

|函数|签名|作用|
|---|---|---|
|写前单路径快照|`snapshot_before_write(run_id, rel_path)`|读现有内容（或标记不存在）→ append 到索引|
|写前多路径快照|`snapshot_paths_before_write(run_id, paths)`|对多个路径循环调用上面那个（给 apply_patch 用）|
|回滚|`rewind_last_writes(run_id, count=1)`|弹出最后 N 条快照并恢复磁盘；返回 `[{path, restored}]`|
|计数|`snapshot_count(run_id)`|还剩多少张快照|

#### `rewind_last_writes` 恢复规则

对弹出的每条快照「从新到旧」

- exists == True → 把 content 写回文件（必要时建目录）「文件已有，内容A就改成内容B」
	
- exists == False → 新建并写入

然后更新索引，去掉已消费的条目。


## 何时拍照

只有使用clutch内置工具的两条路径会自动快照也就是 `builtin_tools.py` 中的

`_tool_search_replace`

查找并替换工具，给AI工具调用的，在真正write_text之前拍照

`_tool_apply_patch`

对patch里涉及的每个路径先拍，再`apply_patch_in_workspace`

## 无快照的范围

- 外部 CLI（Claude Code 等）自己改文件 → 无快照 「CLI在自己的进程读写，用自己的工具」
	
- run_terminal_cmd 里 echo > file → 无快照 「跑终端命令在Shell里执行，没有经过上述两个工具」
	
- 用户在 IDE 里手改 → 无快照

所以验收文档写的是：让 Agent 用 search_replace 改文件，再测 rewind。


## 端到端链路串联

```
┌─ 写入阶段（自动）────────────────────────────────────────────┐
│ 用户 Chat 让 Agent 改文件                                   │
│   → Agent 调 search_replace / apply_patch                  │
│   → _bg_job_run_id() 得到当前 run_id                        │
│   → snapshot_before_write(s)                               │
│         读工作区文件旧内容                                    │
│         append → .clutch/rewind/{run_id}/snapshots.json    │
│   → 真正写入新内容到磁盘                                      │
└────────────────────────────────────────────────────────────┘

┌─ 回滚阶段（用户点按钮）─────────────────────────────────────┐
│ Chat「+」→「回滚文件改动」                                    │
│   → POST /api/runs/{run_id}/rewind  { "count": 1 }         │
│   → rewind_last_writes：弹出最后 1 条快照                     │
│         exists? 写回 content : 删除新建文件                   │
│         更新 snapshots.json                                 │
│   → Chat 追加 Supervisor「已回滚…」并落盘 ClutchState         │
│   → 前端 replaceState → UI 出现回滚提示                       │
│   → 磁盘文件已恢复                                            │
└────────────────────────────────────────────────────────────┘
```

概括起来就是，走内置Agent的ReAct循环时，一旦调到会改文件的工具，工具会内置拍快照逻辑，将旧照给保存下来。当后续需要回滚的时候就通过HTTP，按快照规则进行还原
