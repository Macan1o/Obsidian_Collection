> [!NOTE] 整体逻辑
> 去掉复杂封装，只保留核心流程，使用 fast‑bm25 + jieba 分词 + 百炼 embedding + RRF 融合 。离线一次构建索引，查询时做混合检索，没有多余 Query 改写业务逻辑

## 整体流程

### 【离线构建（只跑一次）】

1. 文档切片得到 `chunks[]`
	
2. BM25：对每个 chunk 做中文分词 → 构建内存 BM25 索引
	
3. Embedding：每个 chunk 调用百炼 `text_type:document` 获取向量，内存保存 `{text,vec}`

> 离线做完，程序重启需要重新构建；个人小库可以把向量、分词结果导出 json 做持久化。

### 【查询链路（用户每问一次执行）】

1. 用户原始 query，**不做任何 LLM 改写增强**
	
2. 两路并行检索
    
    - A 路 BM25：query 分词 → BM25 检索，拿到文档排名列表
	    
    - B 路 向量：query 调用百炼 `text_type:query` 拿到 query 向量，内存算余弦相似度，拿到向量排名列表
    
3. RRF 融合两份排名，去重合并，输出最终上下文片段
	
4. 将片段 + 用户 query 传给大模型生成回答
