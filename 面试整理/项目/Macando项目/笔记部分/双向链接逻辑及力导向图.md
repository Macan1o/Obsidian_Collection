## 写入逻辑细节

### 识别 `[[` 并触发 `WikiLinkList`

> 核心是 Tiptap 的 `Suggestion` 插件，它本质是一个 ProseMirror 插件，持续监听用户输入

```Javascript
// WikiLink.ts

Suggestion({
  editor: this.editor,
  char: "[[",        // 监听这个触发字符
  allowSpaces: true, // 允许搜索词里有空格

  items: ({ query }) => {
    // 用户输入 [[简 时，query = "简"
    // 在所有笔记里模糊匹配
    return getNotes()
      .filter(n => n.title.toLowerCase().includes(query.toLowerCase()))
      .slice(0, 8);
  },

  render: () => ({
    onStart: (props) => { /* 第一次检测到 [[ → 创建 tippy 浮层 */ },
    onUpdate: (props) => { /* query 变化 → 更新候选列表 */ },
    onExit:   ()      => { /* 失焦或选完 → 销毁浮层 */ },
  })
})
```

### 如何插入

> 用户按 Enter / Tab / 点击后，`command()` 被调用

```Javascript
// WikiLink.ts

command: ({ editor, range, props }) => {
  editor
    .chain()
    .focus()
    .deleteRange(range)   // 第一步：删除用户输入的 "[[简历"
    .insertContent({      // 第二步：插入结构化节点
      type:  "wikiLink",
      attrs: {
        id:    props.id,     // "note_1778054551249_19tpy"
        label: props.title,  // "简历简介"
      },
    })
    .insertContent(" ")   // 第三步：插入空格，光标落在节点后
    .run();
},
```

### 差量存储

```Javascript
// [noteId]/route.ts

async function syncLinks(tx, userId, sourceId, newContent) {

  // 第一步：从新内容里提取所有被引用的 id
  const newTargetIds = new Set(extractWikiLinkIds(newContent));
  // 假设结果是 Set { "note_C", "note_D" }

  // 第二步：查数据库里现有的链接
  const existingLinks = await tx.noteLink.findMany({
    where:  { sourceId },
    select: { id: true, targetId: true },
  });
  // 假设结果是 [{ id: "link_1", targetId: "note_B" },
  //             { id: "link_2", targetId: "note_C" }]

  const existingTargetIds = new Set(existingLinks.map(l => l.targetId));
  // Set { "note_B", "note_C" }

  // 第三步：集合差运算
  const toDelete = existingLinks
    .filter(l => !newTargetIds.has(l.targetId))  // note_B 不在新集合里
    .map(l => l.id);                              // ["link_1"]

  const toCreate = [...newTargetIds]
    .filter(id => !existingTargetIds.has(id))     // note_D 不在旧集合里
    .map(targetId => ({ userId, sourceId, targetId }));
  // [{ userId, sourceId, targetId: "note_D" }]

  // 第四步：只操作差异部分
  if (toDelete.length > 0)
    await tx.noteLink.deleteMany({ where: { id: { in: toDelete } } });
  // 删掉 link_1（A→B）

  if (toCreate.length > 0)
    await tx.noteLink.createMany({ data: toCreate, skipDuplicates: true });
  // 新增 A→D

  // note_C 对应的 link_2 全程没有被触碰，createdAt 保留
}
```

### 后端提取节点

```Javascript
// [noteId]/route.ts

function extractWikiLinkIds(content: string): string[] {
  if (!content) return [];
  try {
    const doc = JSON.parse(content); // 把 JSON 字符串解析成对象树
    const ids: string[] = [];

    // 递归遍历整棵 Tiptap JSON 树
    const walk = (node: any) => {
      if (node.type === "wikiLink" && node.attrs?.id) {
        ids.push(node.attrs.id);  // 找到就取 id
      }
      node.content?.forEach(walk); // 递归处理子节点
    };

    walk(doc);
    return [...new Set(ids)]; // Set 去重，防止同一篇笔记被引用多次
  } catch {
    return []; // JSON 解析失败时安全降级
  }
}
```

```
walk(doc)
  walk(paragraph)
    walk({ type: "text", text: "我的 " })       → 不是 wikiLink，跳过
    walk({ type: "wikiLink", attrs: {...} })    → 命中，push "note_xxx"
    walk({ type: "text", text: " 写得很好" })   → 不是 wikiLink，跳过
```

# 技术难点

### Tiptap 原子节点和纯文本存储取舍

**问题**

改用 `atom: true` 的 Node 扩展，直接在 JSON 里存结构化数据，后端遍历 JSON 树匹配 `node.type === "wikiLink"` 即可，彻底绕开文本解析。

```
{ "type": "wikiLink", "attrs": { "id": "note_xxx", "label": "标题" } }
```

### 差量更新 NoteLink

**问题**

查出现有链接和新链接的集合，做集合差运算，只操作变化的部分，未改变的记录原封不动。

### D3力导向模拟器计算坐标

```
const simulation = d3.forceSimulation(nodes)
  .force("link",   d3.forceLink(edges))   // 有边的节点互相吸引
  .force("charge", d3.forceManyBody())    // 所有节点互相排斥
  .force("center", d3.forceCenter(w/2, h/2)); // 整体向中心收拢
```

### 每次 tick 坐标同步到 SVG 元素

```
simulation.on("tick", () => {
  // 更新连线的两端坐标
  link
    .attr("x1", d => d.source.x)
    .attr("y1", d => d.source.y)
    .attr("x2", d => d.target.x)
    .attr("y2", d => d.target.y);

  // 更新节点圆形的位置
  node.attr("transform", d => `translate(${d.x}, ${d.y})`);
});
```
