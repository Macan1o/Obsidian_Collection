## **会话消息（Convex）**

### **链路**

```
用户点发送
  → form.reset()（先清空输入框）
  → clientId = crypto.randomUUID()
  → createMessage(payload, optimisticUpdate)
       → mutationFn.withOptimisticUpdate(...)
       → localStore.setQuery(messages.get, [假消息, ...existing])
  → Convex 执行 message.create
       → clientId 去重（防重试双写）
  → 订阅推送真消息，替换/合并列表
```

> 封装在 `hooks/useMutationState.tsx`：`optimisticUpdate` 有则 `withOptimisticUpdate`，否则普通 mutation。

| **机制**                 | **作用**                                                    |
| ---------------------- | --------------------------------------------------------- |
| `clientId`             | 服务端 `message.create` 查重，弱网重试不双写                           |
| 假消息 `_id` 以 `temp_` 开头 | `Body.tsx` 对已读 `markRead` **跳过** temp id，避免对假消息调 mutation |

### 乐观更新导致的动画闪烁

通过浏览器的`crypto.randomUUID()`生成前端的唯一标识作为`key`,将其存入数据库中。

在前端循环渲染的地方把原先的 `_id` 的 `key` 优先使用前端生成唯一标识的 Id ，这样一来不管是假消息还是真消息，只要key一样就不会销毁DOM，仅仅是组件内部的个别数据更新了，就不会引发二次闪烁。
