# JS语言

## 原型链

> 原型链主要是解决对象属性和方法的查找问题

**原型链的本质上就是一个变量查找机制**。其主要机制是依靠 `prototype` 和 `proto` 两个属性完成的。

`prototype` ： **函数（仅构造函数）** 的专属属性，本质是一个原型对象，是构造函数创建实例的「共享模板」，所有实例会继承其上的属性 / 方法；

`proto` ：**所有对象**的内置原型指针，实例的`proto`会**直接指向创建它的构造函数的**`prototype`。

> 正是由于`Proto`这个层层上指的底层逻辑依靠`prototype`串联起的链式结构叫做原型链。

重要的方法：

`Object.getPrototypeOf` ===> 指的是获取创建该对象构造函数的原型

`Object.setPrototypeOf` ===> 指的是设置创建该对象构造函数的原型

`Object.create` ===> 指的是不依赖构造函数的一种原型继承方法

## 普通对象和Map对象以及Set对象的区别是什么

### 普通对象
- 键只能是字符串、Symbol，如果传其他类型会转为字符串
	
- 不保证严格插入顺序，有先后顺序，Symbol 单独放最后
	
- 没有直接长度，需要 `Object.keys(obj).length` 计算，性能差
	
- 自带原型方法容易出现命名冲突
	
- 只能转数组再循环
### 一般用于
- 静态配置、固定字段（配置项、JSON 结构）
	
- 需要 JSON 序列化传输（Map 不能直接 JSON.stringify）

### Map对象
- 键支持任何类型：数字、对象、数组都可以
	
- 严格按照插入顺序遍历
	
- 直接 `map.size`，O (1) 获取元素数量
	
- 不存在原型键污染，所有键都是手动存入，不会和内置方法冲突
	
- 原生支持 `for...of`、`forEach`
	
- 频繁增删键值对性能更好
### 一般用于
- 键需要对象 / 数字等非字符串类型
	
- 频繁新增、删除、查询数据（树形结构、缓存）
	
- 需要稳定插入顺序、快速获取长度
	
- 数据量大，追求读写性能

### Set对象
> 元素唯一、存任意类型、有序、快速去重

- 数组去重
	
- 快速判断某个值是否存在（查找性能优于数组）
	
- 数据集合运算：交集、差集、并集

## **JS原理**

> 为什么作为一个单线程语言，性能却很强，处理高并发和复杂页面交互时并不卡？

**首先这得益于其核心机制事件循环和非阻塞I/O机制。**

因为我们指的单线程是JS引擎**执行代码的那个线程是单线程**的，浏览器或者Node.js是多线程的，因此当主线程遇到耗时任务时，把这些任务交给浏览器的其他线程去处理，等到同步代码执行完了，再把回调函数推给主线程去执行。

其次得益于多线程的宿主环境「浏览器、node.js」让主线程永远处于高效率的运转之中。如果遇到**大量 CPU 密集型计算**的极端情况，此时要开 `worker` 或Node多进程 。

## **执行上下文和作用域链**

> 执行上下文：JS引擎执行代码时抽象出的环境，包括**变量**、**函数**、**this指向**等信息
> 
> **作用域链**：执行上下文组成的查找变量的链条，具有查找变量的机制「而原型链是查找对象属性和方法」

并且因为作用域链的**持久化引用变量**，因此变量回收机制无法对变量回收清除。因此实现了闭包的底层逻辑

## **闭包**

> 闭包本质上是一个函数与其词法环境的引用，相当于一个函数用到了外部的资源，函数本身和外部数据产生了关联，因此形成了一个闭包

**闭包的影响**：

**保留了作用域状态**：延长生命周期可以执行一些延迟执行逻辑，也可以避免被变量回收。比如LLM项目中通过闭包实现了网络分包数据同步，还有`Promise all`的计数器实现了`Promise`对象和结果的同步，防抖、节流，`useState / useEffect / useCallback / useMemo` **全靠闭包**。

**避免变量污染**：只在其固定的作用域中发挥作用，但是频繁使用会导致内存泄漏，需要手动结束引用

## **箭头函数与普通函数区别**

### 箭头函数

- 是一种新特性语法，没有自己的`this`，而是继承自外层
    
- 没有 `arguments` 参数需要借助（`...args`）不能构造、没有`prototype`
    
- 因为语法简便，常常用在回调函数上解决`this`丢失问题


### 普通函数

- 在定义方法构造函数上占有优势，`this`指向其调用者。

## **Promise**

`Promise` 是异步编程的一种核心机制。其核心特性就是状态一旦改变就不可逆转，本质是一个状态机，保存着未来才会结束的异步操作结果。通过`then`方法实行链式调用，避免了一层层的回调嵌套。其链式调用的核心逻辑就是不管返回什么值，底层都会包装并返回一个全新的`Promise`对象，结合其状态不可变，形成了`then`方法的链式调用。

另外在事件循环中，`promise`的构造函数代码是执行同步函数，`then`和`catch`里面的回调函数是属于微任务队列

## **New 的操作符**

1. 创造一个全新的空对象
    
2. 将新对象的隐式原型指向构造函数的原型对象上
    
3. 将构造函数的`this`绑定到这个新对象上，并执行构造函数的内部代码
    
4. 判断构造函数的返回值，如果是非空对象，就返回该对象。如果不为空，就返回刚才创建的新对象


**Object.create只是完成了原型链的绑定，但是此时里面是空对象，因为this指向是指向全局的，里面没有属性和方法，当把this指向的时候，才相当于继承了构造函数的属性和方法**

## **继承**

> JS继承的核心本质上是 让子类实例的原型链指向父类的原型/实例 从而共享父类的属性和方法

### **构造函数继承**

父类实例私有化，并且可以**给父类传参**。但是**只能继承父类**的属性和方法，无法继承原型链上的

### **原型链继承**

能继承原型链的属性和方法，但是**父类实例属性会被所有子类实例共享**，且**无法传参**给父类

### **组合继承**

兼顾私有化和复用性，但是会执行两次构造函数，可能会造成**原型链污染**

### **类继承**

类继承解决了上述问题，并且通过`super`方法绑定`this`并且传参给父类构造器

**继承中向父类传参的根本目的是为了对子类实例对象的个性化定制**

## **this指向丢失问题探讨**

**函数作为回调函数传递**

```
const obj = {
  name: '张三',
  sayName() {
    console.log(this.name); // 预期 this 指向 obj
  }
};

// 错误：定时器回调中，this 指向 window（浏览器）/ global（Node）
setTimeout(obj.sayName, 1000); // 输出 undefined

// 原因：setTimeout 会将 obj.sayName 作为独立函数执行，调用者不是 obj
```

**函数作为普通变量赋值后调用**

```
const obj = {
  name: '张三',
  sayName() {
    console.log(this.name);
  }
};

// 错误：将方法赋值给变量，调用时 this 指向 window
const fn = obj.sayName;
fn(); // 输出 undefined

// 原因：fn 是独立函数，调用者是全局对象（非严格模式）/ undefined（严格模式）
```

**解构赋值提取对象方法**

```
const obj = {
  name: '张三',
  sayName() {
    console.log(this.name);
  }
};

// 错误：解构后，sayName 失去原对象上下文
const { sayName } = obj;
sayName(); // 输出 undefined

// 原因：解构后的 sayName 是独立函数，调用者不是 obj
```

## **防抖节流**

> 两者都是限制高频事件触发的手段（滚动、输入框输入、按钮点击、窗口resize）

**节流**是「**固定频率执行**」，按照固定的节奏执行（**滚动加载数据、高频点击按钮**）

**防抖**是「**关注最后一次触发**」，高频触发时会合并成一次执行（**输入框停止输入搜索**）

## 泛型 (Generics)

> **本质**：**类型参数化**。在定义函数、接口、类时不预先指定具体类型，而是在使用时再动态传入。

```
function identity<T>(arg: T): T { return arg; }
```

### 常用内置工具类型 (Utility Types)

- `Partial<T>`：将 `T` 中的所有属性变为**可选**。
    
- `Required<T>`：将 `T` 中的所有属性变为**必选**。
    
- `Pick<T, K>`：从 `T` 中提取一组属性 `K` 来构建新类型。
    
- `Omit<T, K>`：从 `T` 中排除一组属性 `K`，用剩下的属性构建新类型。


---

### 类型推断与类型守卫

- **类型推断**：TS 根据上下文自动推导出变量类型的能力（例如 `let a = 1` 自动推断为 `number`）。
    
- **类型守卫 (Type Guards)**：在运行期通过某些条件判断，**收窄**变量的类型范围。常见手段：`typeof`、`instanceof`、`in` 关键字，或者自定义类型谓词（`function isString(x: any): x is string`）。

## BFC（块级格式化上下文）

- **定义**：页面上一个独立的隔离渲染区域，内部子元素的布局不会影响到外面的元素。
    
- **触发条件**：`overflow: hidden / auto`、`display: flex / inline-block`、`position: absolute / fixed`。
    
- **核心应用**：
    
    1. **清除浮动**（让父元素包裹浮动的子元素，解决高度塌陷）。
        
    2. **防止垂直 margin 重叠**（把其中一个元素包裹在独立的 BFC 容器中）。

## 水平垂直居中方案

```
/* 方案 1：Flex 布局（最推荐） */
.parent { display: flex; justify-content: center; align-items: center; }

/* 方案 2：Absolute + Transform（绝对居中，不需要知道子元素宽高） */
.parent { position: relative; }
.child { position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%); }

/* 方案 3：Grid 布局（最少代码） */
.parent { display: grid; place-items: center; }
```

## **CSS隐藏元素的方法**

`display：none` ---> 元素在页面上彻底消失 导致浏览器重排和重绘

`visibility ：hidden` ---> 不会触发重排但会触发重绘 DOM结果存在

`opacity ：0` ---> 一般也会触发重绘

## **重排和重绘**

**重排**： 布局引擎根据各种样式计算盒子在页面的大小和位置 --> 引擎根据样式计算盒子的大小和位置

**重绘**：计算好大小和位置后 对每个盒子特性进行绘制 ---> **对每个盒子特性进行绘制**

### **浏览器解析渲染机制**

```
解析HTML生成DOM树 

解析CSS生成CSSDOM树

DOM树和CSSDOM树结合 生成渲染树  ---> render tree（渲染树）

根据渲染树进行回流 得到节点的几何信息 （回流）

根据渲染树和几何信息 得到节点的绝对像素 （重绘）

将结果发送到GPU 展示在页面上  
```

### **减少重排重绘**

1. 避免设置多项内联样式
    
2. 避免使用`table`布局
    
3. 对于复杂动画尽可能脱离文档流 ---> `position ：fixed （浏览器窗口） / absolute（最近的已定位祖先元素`
