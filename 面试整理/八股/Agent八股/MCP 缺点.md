## 统一鉴权

> 每个外部 MCP‑Server 可能各玩各的认证，Agent 要分别处理每一套鉴权逻辑，很乱。

- A 服务用 API Key 放环境变量
	 
- B 服务用 token 走 stdin 传入
	 
- C 服务不需要鉴权内网裸跑
	
- D 服务用 OAuth

由 client 统一管理密钥、token、权限，再分发给各个后端 MCP Server。架设一层网关中间层预处理。


## 统一超时

各个外部 MCP Server 是独立进程，会出现以下问题

- 某个工具卡死、网络卡住、外部程序死循环，一直不返回
	
- 有的 server 默认 30s 超时，有的 120s，有的完全没有超时控制

如果不做统一超时，整个 Agent ReAct 循环就挂住卡死。


## 错误回灌格式

> 把外部 server 抛出来五花八门异常，转换成 Agent ReAct 循环能读懂的标准错误报文。

各个 MCP 外部服务抛出的错误千奇百怪

- 有的返回 json 错误对象
	
- 有的直接 stderr 打印一堆堆栈、python/go 崩溃日志
	
- 有的进程直接崩溃退出，只返回进程退出码
	
- 有的返回人类可读大段中文报错；有的返回原始堆栈

如果不处理，大模型会被杂乱堆栈、raw stderr 日志干扰，乱推理、乱重试。

因此mcp_client 捕获外部 MCP server 的所有异常：进程崩溃、调用报错、超时、非法参数。把各式各样原始错误，清洗、包装成**统一结构的工具失败消息**，再喂回 ReAct 循环给 LLM。
