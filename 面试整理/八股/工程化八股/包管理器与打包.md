## npm/ pnpm/ yarn

### npm

采用**依赖扁平化**，把依赖提升到顶层；容易出现**幽灵依赖**，能直接引用没在`package.json`声明的包，一旦底层依赖变动 / 删除，项目直接报错。

### pnpm

**严格模拟原始依赖树**，根目录只放项目**显式声明**的依赖；彻底杜绝幽灵依赖，同时采用**硬链接 + 内容寻址存储**，磁盘占用更小、安装更快。

### Yarn（yarn）

早期为解决 npm 缺陷而生，**采用扁平化依赖**和 npm 类似；自带**lock 锁文件**、依赖版本锁定更严谨，安装速度、稳定性优于旧版 npm，但**依然存在幽灵依赖问题**，没有优化依赖树结构。

## 三种打包模式

### WebPack

**全量打包模式**：先**递归解析项目所有模块**，打包成一个 / 多个 bundle，再启动服务；各类功能需**手动配置 Loader、Plugin**。

### Vite

**按需编译模式**：开发环境**不整体打包**，先直接启动静态服务；**浏览器请求哪个模块，就实时编译哪个**，冷启动、热更新速度极快。

### Next.js

**混合编译 + 服务端构建**

不仅具备按需编译 + 热更新，同时基于 Webpack/Turbopack实现全量打包 + 优化，内置所有能力并自动完成代码分割、**SSR/SSG/ISR 编译**、**路由打包**、服务端组件分离
