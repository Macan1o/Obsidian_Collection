## 前端性能优化

> 分析工具：Chrome DevTools Performance、Lighthouse、WebPageTest、bundle analyzer。

**优化方向：**

- **代码层：路由懒加载（React.lazy / defineAsyncComponent）；Tree-shaking 去除死代码；按需引入组件库（如 import Button from 'antd/Button'）。
    

- **资源层：图片懒加载（IntersectionObserver）；使用 WebP/AVIF 格式；字体子集化；CSS/JS 压缩与 gzip/brotli。
    
- **网络层：CDN 分发静态资源；HTTP/2 多路复用；资源预加载 `<link rel="preload">`；Service Worker 缓存。
    
- **渲染层：SSR/SSG 提升 FCP；骨架屏占位；Critical CSS 内联；避免渲染阻塞。
    
- **React 专项：Suspense + lazy 分片渲染；useDeferredValue 延迟非关键渲染。
    
- **Vue 专项：keep-alive 缓存路由组件；defineAsyncComponent 异步组件。


先说「分析工具找瓶颈」，再说优化方案，体现有数据驱动的思维。

## 封装组件的数据流

> 封装组件的核心是**单向数据流原则**，通过几个关键的方式来平衡封装性和灵活性

**首先是输入输出** —>

用Props接受父组件的配置数据 （`data` 、`loading` ）；用 `Events` 触发交互回调 （`change` 、 `submit` ），子组件不直接修改数据，而是通过事件通知父组件更新

**然后是扩展能力** —>

用 Slot 进行UI定制，比如表头、单元格自定义；用 **Expose Methods** 通过`ref`暴露方法，比如表单的`validate()`、`reset()`，让父组件能主动控制子组件。「`ref="formRef"` 」然后进行主动控制「`formRef.value.validate()`」从而让父组件能够直接控制子组件

## **大文件分片上传**

> 大文件上传

首先先定义切片函数，将数据进行切片

然后递归读取切片，每读完一个片段触发钩子，生成`MD5`唯一标识。

读取完所有切片后，将哈希值发请求传给后端。后端进行对比，查看有无重复的切片。

前端根据`filter`过滤出后端有的切片，剩下的切片按照异步调度器传给后端

> 前端大文件上传，token过期了怎么处理，必须做断点续传 + 无感刷新 Token + 暂停续传。

**正确的处理方案是**：

1. 后端返回token过期的话，前端立刻暂停当前上传。
    
2. 前端调用刷新token的接口，获取新的token
    
3. 然后断点续传，只上传失败的切片的剩余的切片。
    
4. 如果刷新token也过期，则回到登录页，重新登录后上传。
