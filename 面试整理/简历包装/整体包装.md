## 模块一：工作经历

我们公司主要是做IAA休闲游戏的项目，然后我作为AI应用的职责就是快速完成一款产品从0到1落地然后到应用商城备案，比如小米、Vivo、Oppo、荣耀，避免被其他公司抢先备案游戏名。因为作为中台承接六个项目组的需求嘛，就需要搭建一个工作流完成全链路的开发过程。

一开始跟 AI 一步步聊，质量不稳定；后来把高质量套路沉淀成 Skill，形成多链路节点监督机制

	规则与红线确认机制
	功能选型
	出设计稿
	形成视觉资产
	按稿还原
	粘性打磨「间距呼吸感、或者一些简单动效」
	数据闭环和冒烟测试

经过这套流程过后我发现最后质量相对来说比较容易把控。输出结构比较统一。并且后续如果增加节点的话也方便配置。

后来就是既然节点链路的话我觉得可以打造一个工作流，刚开始是打算用n8n的，后来发现n8n它能跑节点，但执行黑盒，人工随时叫停也不顺手。因为我们需要过审，所以需要对UI和功能有要求。于是我就打造了一个基于LangGraph的多 Agent 编排与监督控制台。状态可看、审批可拦、输出可控。应用过审率基本保持在85%以上

通过调用 Claude CLI 只用 Claude 自己的工具/MCP，从而完成功能、出图以及其他操作

### 工作包装

#### 介绍背景

在工作上，我的部门在公司中台，主要是负责搭建工作流来对接五个项目组。因为他们主要是做 IAA 休闲游戏的项目，他们给出产品名称，我需要根据这个产品名称从 0 到 1 快速落地具体的工具产品然后上架应用商店。先抢先备案，等项目组那边产品做出来之后再更包，同时避免被其他公司抢先备案游戏名

#### 工作过程

刚开始的时候我先固化成一套 skill ，包括规则红线检查、功能选型、出稿、视觉资产、还原这几个节点。不断针对节点打磨

对使用过程中出现的共性问题，固化成一套提示词补丁来完善 skill 。

随着 skill 逐渐使用过程中，我产生了一个做出一款应用的想法，算是提高我的工程化能力吧。

- 然后我就做了一款基于 LangGraph 的多 Agent 智能体编排控制台。
    
- 支持 画布SOP 和 JSON 两种场景编排工作流，分别对应简单、复杂场景；
    
- 支持包括图级、工具级人工审批节点涉及到的条件编译和非条件编译；
    
- 同时支持 PTY 复用进程和环境，支持跑对应的 CLI和内置云端大模型两种方式。
    
- 通过 WS 和 HTTP 两种方式通信；


为了实现上述多条异构执行链，我还专门设计了自定义状态管理 State。从而大大提高了我的工程化能力
