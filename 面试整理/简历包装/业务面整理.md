## 平常是怎么学习的

> 我有两个层面的学习，分为理论学习和实战源码学习。

关于理论学习我的习惯是先找锚点。新技术如果和已有知识有重叠，从重叠处切入会快很多。比如从JS的角度映射到Python的学习中。如果是全新领域，我会先跑通一个最小 demo 把主链路走一遍，有了问题意识再去啃文档，比从头读文档效率高得多。

> 关于实战源码学习，我分为了三个阶段。

- 第一个阶段是先建立骨架认知，先建立各个模块间的全局心智模型。对全局的边界有一个把握「<mark style="background:#d3f8b6">端到端怎么走</mark>」
	
- 第二个阶段是逐模块深挖吃透各个模块的技术细节「<mark style="background:#d3f8b6">问题是什么，怎么解决，为什么这么选，边界在哪</mark>」
	
- 第三个阶段就是细节查证，通过双链连接对比较重要的逻辑单独拎出来说明。「<mark style="background:#d3f8b6">比如LangGraph的单参回调特性解决方案</mark>」


## 简单说说做项目的思路

随着做工程化的项目并且积累经验后，我越来越觉得核心不是某个库怎么用，而是在正确的生命周期、正确的时机处理状态，并把兜底做扎实。

比如我的 clutch 项目。先看输入输出，输入的是用户在各个节点配置好的提示词。输出的是一个从0到1的产品。

然后开始思考我要借助什么载体实现这一过程 ？因此就先技术调研，发现 LangGraph 比较适合。以此类推选择好各个功能适合的载体，监督用 WebSocket 投影 ClutchState，本地执行用 CLI / Hybrid PTY。然后就是根据这一核心链路构建工具函数帮助我们实现产品的构建。中间穿插着各种兜底处理机制保证工程项目的健壮性。从而实现完整链路的跑通。

跑通后就要对质量进行提高，比如多 Agent 输出与交接？权限逻辑如何实现？多种 Agent 的逻辑分流？然后慢慢丰富完善这个项目。再进行功能迭代更新。

在这一个过程中出现bug是很正常的，系统化排查解决bug能力也是提高自己工程能力关键的一环
