#发布订阅模式

---
> 解耦「**数据生产者**」和「**数据消费者**」，生产者只管发布变更信号，完全不用关心有多少、哪些消费者；消费者自行订阅信号，收到通知后执行自身更新逻辑。

#### 一个事件有多个回调函数执行

### 订阅「`Subscribe`」

消费者主动把自己的回调函数交给调度中心，当数据变了会通知，例如：

	组件调用 `store.subscribe(rerenderNotify)` 注册更新回调。

### 发布「Publish / Emit」

数据发生变化后，只通知调度中心「数据更新」，中心遍历所有已订阅的回调，统一执行一遍。

### 对比硬编码

	硬编码

```typescript
function updateStore() { 
state.xxx = 123 
ComponentA.forceUpdate() 
ComponentB.forceUpdate() 
ComponentC.forceUpdate() 
}
```

	发布订阅

将需要更新的组件统一订阅到一个`Set`仓库`listener`集合中，然后统一收束到一个更新函数中遍历更新
