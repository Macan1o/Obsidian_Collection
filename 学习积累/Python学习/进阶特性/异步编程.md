> 与JS的区别

- Python写好异步逻辑后需要通过事件循环`asyncio.run()` 调度才能正确执行异步逻辑
	 
- JS则是天生支持异步，会自动执行逻辑

## 基础语法对照

#### JS语法

```Javascript
// 异步函数
async function fetchData() {
    // await 等待Promise完成
    const res = await fetch("url");
    console.log(res);
}
// 调用返回Promise
fetchData();
```

#### Python

```Python
import asyncio

# async 定义协程函数
async def fetch_data():
    # await 等待可等待对象完成
    print("开始请求")
    await asyncio.sleep(2)  # 模拟IO等待，不会阻塞
    print("请求结束")

# ⚠️重点：直接调用 fetch_data() 不会执行函数内部！
# 只会创建一个【协程对象】，相当于JS里「只创建Promise但没有触发执行」
coro = fetch_data()

# 需要事件循环去调度运行
asyncio.run(coro)
```

## Python中并发执行多个进程

	顺序执行，一个个来，效率低

```Python
async def main():
    await fetch_data()
    await fetch_data()

asyncio.run(main())
```

	并发执行（同时发起），对应 JS `Promise.all`

```Python
async def main():
    task1 = fetch_data()
    task2 = fetch_data()
    # gather 收集多个协程，并发运行
    await asyncio.gather(task1, task2)

asyncio.run(main())
```

	Task任务`asyncio.create_task()` 提前创建任务，自动加入事件循环调度，可以实现后台并发。

```Python
async def main():
    # 创建任务，立刻开始调度执行
    t = asyncio.create_task(fetch_data())
    print("做其他事情")
    await t  # 等待任务完成
```


## 注意事项

- **await time.sleep () 毫无异步效果！**
    
    `time.sleep()` 是同步阻塞，会卡死整个事件循环；异步等待必须用 `await asyncio.sleep()`
    
    类比：不能在 await 里放同步耗时循环。
    
- 异步≠多线程
    
    协程是**单线程内切换**，适合 IO 密集型；CPU 密集型任务不适合 asyncio。
    
- 同步库不能直接 await
    
    requests、普通 time、同步数据库都阻塞事件循环，要用异步版本：aiohttp、async 数据库驱动。

## 项目中体现

> `asyncio.to_thread()` — 把同步阻塞代码桥接到异步世界

对于一些同步函数比如 `route_engine()`、`run_mcp_react_loop()` 被 FastAPI 异步 handler 调用时如何保证不阻塞事件循环？

	用 asyncio.to_thread() 把它们扔到独立线程池执行

```Python
# chat_runner.py 第 1458 行
result = await asyncio.to_thread(
    route_engine,             # 同步函数
    agent_name=agent_ref,     # 参数原样传递
    prompt=text,
    cwd=cwd,
    ...
)
```

	await asyncio.to_thread(fn, *args) 的意思是把 fn(*args) 交给一个单独的线程去跑，我等它跑完拿结果，但事件循环不会被堵住


> asyncio.create_task() — 后台常驻任务

	把一段 async 协程丢进事件循环，和其他异步代码并行跑

```Python
# 起一个永不退出的循环任务
task = asyncio.create_task(_sweep_shell_sessions())

# 起一个即弃的后台任务（不关心返回值）
asyncio.create_task(_prefetch_cc_switch_bundle())
```

	create_task() 不阻塞当前协程，任务在后台跑。它需要传入一个协程对象（async def 的调用结果），不是普通函数。关闭时用 task.cancel() + await task 干净退出


> @contextmanager — 同步上下文管理器


	@contextmanager 把生成器函数变成 with 语句管理器。yield 前的代码在 with 进入时执行，yield 后的 finally 在退出时执行——和 @asynccontextmanager 结构一模一样，只是一个同步一个异步。

```Python
# workspace_cli_lock.py — 防止同一 workspace 多个 CLI 并发写冲突
@contextmanager
def workspace_cli_turn(workspace_path, *, timeout_s, on_waiting=None):
    lock = _get_lock(workspace_path)
    acquired = lock.acquire(timeout=timeout_s)
    if not acquired:
        raise ShellSessionError("timeout")
    try:
        yield                            # 锁持有期间
    finally:
        lock.release()                   # 无论如何释放锁


# 调用方（shell_exec_runtime.py）
with workspace_cli_turn(session.workspace_path, timeout_s=..., on_waiting=...):
    return _run_turn()                   # 锁保护的临界区
```
