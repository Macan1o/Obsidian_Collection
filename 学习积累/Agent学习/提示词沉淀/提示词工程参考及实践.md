#提示词

既然使用AI提效了，那么最直接跟AI交互的媒介就是提示词。下面是使用AI出现的一些问题和需要调整的情况

---
## 工程参考

##### 过去
```
请帮我实现将后端的数据渲染到前端页面上
```
##### 现在
```
请帮我写一个高效的 JS 递归函数来遍历这个树状结构，它能在0.5秒内吐出完美且带注释的代码
```

---

在我日常开发中也确实出现了这个问题，AI有时候会以MVP为标准设计逻辑，但是在生产中我们需要考虑到并发等一些问题，比如：

	我的笔记项目设计个人动态模块的时候，AI没有考虑到数据量过大，导致单次查询耗时急剧拉长，长期占用数据库连接池，引发连接超时。

所以需要在提示词上<font color="#0070c0">加上限定词</font>，才会补全生产级优化方案：

	明确要求「支持海量数据、高并发、分页、缓存、防超时」

---

> 开发功能的提示词模板概括的一些参考标准，具体开发根据实际取舍

通用
```
1. 大数据场景：禁止一次性拉取/渲染全量数据，必须分页/游标分页/虚拟滚动；限制单次请求返回数据量，避免大报文超时；
2. 并发&高频访问：做缓存、防抖节流、请求合并、重复请求拦截，减轻服务与数据库压力；
3. 超时&资源防护：规避长耗时请求，设置合理超时时间，防止连接池/渲染线程阻塞；
4. 异常容错：全覆盖空数据、加载失败、网络异常、接口报错兜底，友好降级展示；
5. 性能规范：减少重复请求、避免冗余渲染、不使用全表查询、按需加载；
6. 边界兼容：海量数据、弱网、低性能设备、极端用户场景全部兼容；
7. 安全基础：参数校验、防越权、避免接口暴露敏感数据。
```

前端
```
角色定位：资深全栈工程师，所有设计、代码均按照线上生产环境标准输出，禁止MVP最简Demo实现，必须提前兼容大数据量、高并发、接口超时、资源占用、边界异常、容错降级等线上问题，不写仅本地小流量可用的简易逻辑。

业务需求 ： XXXXXXX

1. 海量列表必须实现虚拟滚动，防止DOM节点过多页面卡顿； 
2. 列表刷新、滚动增加节流，按钮点击增加防抖，防止重复发请求；
3. 接口统一封装超时拦截，超时展示重试按钮；
4. 数据本地缓存，避免重复请求相同用户动态；
5. 拆分组件、懒加载、避免不必要的响应式重渲染；
6. 空列表、加载中、加载失败、无网络多状态分层展示；
7. 大图片懒加载，防止页面加载阻塞。
```

后端

```
角色定位：资深全栈工程师，所有设计、代码均按照线上生产环境标准输出，禁止MVP最简Demo实现，必须提前兼容大数据量、高并发、接口超时、资源占用、边界异常、容错降级等线上问题，不写仅本地小流量可用的简易逻辑。

业务需求：XXXXXXXXX
   
后端专属强制要求： 
1. 海量数据采用游标分页，禁止偏移分页，建立user_id联合索引，杜绝全表扫描； 
2. 热点用户动态增加Redis缓存，处理缓存穿透、缓存击穿； 
3. 限制SQL最大执行时间，防止慢SQL占用数据库连接池导致连接超时； 
4. 请求入参严格校验，限制单页最大返回条数，防止超大报文； 
5. 高并发场景增加简单限流，大量请求时缓存降级； 
6. 统一异常捕获，超时、数据库异常返回友好业务码，不暴露底层报错； 
7. 避免SELECT *，只查询业务所需字段，减少IO开销。
```

## 工程实践


目前我的工作链路主要总结为两步「最重要两步」

- AI 生成落地应用方案及功能
	
- AI生成UI页面绘图提示词

我尝试过讲上述链路总结为两个工作流节点，但是最终输出的结果跟预期有点不符。具体体现在：
假如我输出「龙猫消消」这款应用，他功能上很自然地就往游戏上面靠，但是游戏往往需要在UI上下功夫，必须打磨好相关UI图标，而本身基于提示词实现UI生成就不是那么成熟，往往会导致这应用实现不了。这就出现了AI提示词最典型的「**AI 路径依赖**」和「**跨模态能力错位**」问题

我需要在链路间进行监管。比如这款应用可以设计下面的功能。这就需要增加中间节点参与产品的打磨

#### 功能举例

```
【生活减法向】龙猫极简预算与债务消消账本
核心痛点： 市面上的记账软件越来越臃肿，充斥着理财广告、社区分享和复杂的图表，用户只想单纯记录自己还能花多少钱，且不想让财务数据上云。
功能定位： 减法原则的纯本地记账与预算消耗工具。
“消消”的玩法设计：
预算消消乐： 不同于传统记账“从零往上涨”，这款应用倡导“做减法”。月初设定一个总预算（比如3000元），变成一个装满橡果的进度条。每记一笔账，橡果就会被龙猫吃掉一部分（消除预算）。
债务/人情消消乐： 专门开辟一个“欠款/借出”板块。朋友还了钱，或者你还了信用卡，点击“消除”，该笔账目直接清零。
龙猫的治愈融合： 龙猫的肚子代表你的预算余额。余额充足时，龙猫胖乎乎地躺着闭目养神；当预算快被“消消”完、超支时，龙猫的肚子会缩水，变成一副委屈巴巴、吃不饱的表情。
离线大招： 财务数据极其敏感，纯离线存储让用户完全不用担心泄露。而且因为不需要加载云端数据，记账速度可以做到“秒开、秒记、秒走”。
2. 消除：坏习惯 —— 行为减法与戒除记录器
核心痛点： 想戒烟、戒熬夜、戒零食、戒奶茶，但市面上的习惯养成软件大多是“让人多做加法”（比如坚持跑步、坚持读书）。有时候，“不做某些事”比“坚持做某些事”更难，且这类隐私用户不想公开。
功能定位： 纯本地的“坏习惯消灭”打卡工具。
“消消”的玩法设计： 玩家输入自己想要“消灭”的坏习惯。每坚持一小时或一天没有破戒，代表该习惯的黑色阴影条就会被“消除”一点。如果中途破戒，就点击“重置”。
龙猫元素： 坏习惯被具象化为森林里的“害虫”或者“枯叶”。你坚持得越久，枯叶被消除得越多，大树就会重新长出绿叶，龙猫就会在树下快乐地荡秋千。
3. 消除：碳足迹 —— 个人绿色低碳生活账本
核心痛点： 很多人想践行环保，但缺乏量化和反馈。同时，这是一种纯粹的个人生活方式选择，不需要复杂的社交攀比。
功能定位： 极简的本地减碳行动日志。最契合龙猫“守护大自然”的动画内核。
“消消”的玩法设计： 记录你的绿色行为来“消灭碳排放”。比如：今天自带环保杯（消除 50g 碳）、步行代替开车（消除 200g 碳）、光盘行动（消除 100g 碳）。
龙猫元素： 你的目标是把每天的碳足迹“消消消”直到清零（碳中和）。每消灭一部分碳排放，界面上的小树苗就会长大一点，最终汇聚成一片属于你和龙猫的橡树林。
```
